# 隔离测试环境与人工验收清单

本轮状态：已准备独立测试配置与虚构数据，已在开发环境验证；腾讯云部署需确认服务器IP、安全连接与测试域名后进行。不要把开发环境的localhost当作你电脑可访问的网站。

## 你现在需要做什么

1. 打开腾讯云控制台 → 轻量应用服务器 → 找到之前部署空间大师的香港实例。
2. 在实例详情复制“公网IP”发给我。如果没有实例，切换地域至香港，确认购买时的账号。
3. 密码、私钥、短信验证码不用发。下一步根据已配置的安全连接方式处理服务器访问。
4. 没有域名也可以继续：先通过SSH隧道进行受保护验收；浏览器只能访问本人电脑的localhost隧道地址，不直接暴露3301端口。测试域名与HTTPS确认后再添加单独入口。

## 测试账号用途

密码由部署后的私有凭据文件安全交付，不在公开仓库中固定。不要将生产密码复用到这些账号。

| 账号 | 操作范围 |
| --- | --- |
| qa_admin | 平台用户、供应商及审计；不自动访问企业X/Y私有项目 |
| qa_xadmin | 企业X管理员：成员、产品、客户、项目转派 |
| qa_yadmin | 企业Y管理员：看不到企业X项目与产品 |
| qa_designer | 同时加入X/Y，另有个人空间；只看分配企业项目 |
| qa_departed | 已从X撤权，仍保留Y和个人空间；X访问应拒绝 |
| qa_client | 受邀客户：方案/BOM确认、自购导出或平台采购选择 |
| qa_supplier_a | 桌椅供应商，仅自身采购单 |
| qa_supplier_b | 灯具供应商，仅自身采购单 |
| qa_outside | 无关账号：不应看见上述企业和客户提交 |

## 样例与金额

- 企业X：“验收01·编辑保存”“验收02·自购交付”“验收03·平台采购（付款关闭）”“验收04·预置沙箱供货单（非真实交易）”。
- 产品：桌1250元、椅800元、灯300元，各1件，商品总额2350元（API整数分235000）；另有原有柜体，不进入采购清单。
- 桌/椅属于供应商A，灯属于供应商B。产品无真实GLB，显示线框，不能用来验收材质保真。
- 初始基线已有1张`paid_sandbox`销售样例、2张`pending`供应商采购单，仅用于供应商接单验收。这是种子脚本预置的沙箱记录，没有实际收款。
- 所以“自购不生成订单”的正确判断是订单数量不增加，而不是要求整个环境始终0订单。

## 建议按此顺序验收

每项记录“通过/失败/待确认”，附账号、项目名、操作、实际结果、截图与时间；截图避免包含密码。

| 编号 | 登录账号与操作 | 预期 |
| --- | --- | --- |
| QA-01 | qa_designer登录，切换个人、X、Y | 三个真实空间；当前空间和岗位可见；企业Y不出现X产品 |
| QA-02 | 打开“验收01·编辑保存”，拖动桌子、调整灯高度，保存刷新重开 | 位置、高度、版本保存；保存失败会显示原因，不显示假成功 |
| QA-03 | 在草稿画L形墙、拖墙角、调整墙长 | 无需输入坐标表；非法轮廓或家具越界应阻止保存。先保留正常项目，再试错误轮廓 |
| QA-04 | 切换2D/3D，隐藏墙体观察，再显示/隐藏顶面 | 同一场景；模型缺失是线框，无伪装实物；顶面隐藏不删除灯具 |
| QA-05 | qa_yadmin或qa_outside查看项目/客户审阅列表 | 无X项目和客户提交；已知项目链接/API亦无权限 |
| QA-06 | qa_departed登录 | 只有个人与Y；无法读取X在途项目，账号本身仍可登录 |
| QA-07 | qa_xadmin把离职成员的企业项目转派给qa_designer | 新设计师获得项目；历史记录保留 |
| QA-08 | qa_client打开“验收02·自购交付”，查看平面与清单，发布批注 | 3个SKU，总额2350元，无成本字段/供应商内部报价 |
| QA-09 | 仅点“确认设计”，设计师查看 | 不能终审；客户再“确认BOM”后，设计师才可终审 |
| QA-10 | qa_designer终审验收02，qa_client选“自行采购并交付清单” | CSV含3个SKU与正确金额，不含成本；原有柜体不计采购；销售单/采购单数量不增加 |
| QA-11 | 用验收03走双确认、终审、客户选平台采购 | 新增2350元`awaiting_payment`订单；因付款入口关闭，不会标记真付款，也不新增采购单 |
| QA-12 | qa_supplier_a与qa_supplier_b分别查看“供应商接单” | A仅桌椅，B仅灯；不见另一供应商采购数据及客户销售价 |
| QA-13 | 两供应商分别对预置采购单接单、发货 | 仅按pending→accepted→shipped，操作结果刷新保留 |
| QA-14 | qa_xadmin再邀请一个已有测试账号；对方登录“成员与邀请”接受 | 邀请未接受前无企业访问；接受后按岗位生效 |
| QA-15 | 技术人员在隔离窗口重启QA服务 | 账号、项目、确认、采购状态保留，旧3000/3100/3200服务不受操作影响 |

可选修改意见分支：先让客户在尚未确认的方案点“退回修改”，设计师保存后重新提交；客户应看到新版本，旧确认不能沿用。此操作会消耗现有样例状态，建议在新建复制项目中测试，或完成基本流程后再做。

## 本轮不验收

真实GLB材质和100MB以上模型、CAD/DWG/DXF/实拍自动识别、复杂碰撞/工程规则、正式支付与退款、物流安装/售后、AI/计费均不作为本轮已完成能力。供应商预置沙箱单不能证明真实交易已上线。

## 技术准备步骤（由我或运维执行）

1. 用`deploy/staging/preflight.sh`只读检查主机资源、端口、旧容器名称及Node/Docker/Nginx版本；不输出密钥，不重启服务。
2. 核对3301空闲、磁盘余量、旧目录与卷，先备份。2核2GB主机建议在其他构建机生成版本化镜像，再传入服务器，不在旧服务运行时重型构建。
3. 新版本代码可本机运行`npm ci && npm run build`；种子初始化`npm run qa:seed -- /全新/QA数据目录`，返回凭据文件路径，不打印密码。
4. `QA_DATA_DIR=/QA数据目录 npm run qa:start`只绑定127.0.0.1:3301。持久运行需进程管理或独立Compose，当前终端启动不是长期托管。
5. Docker模板在deploy/staging：显式QA_IMAGE/QA_UID/QA_GID/QA_DATA_PATH，读写数据仅绑定QA目录。512MiB内存/0.75CPU是初始上限，部署前按主机余量确认；Docker镜像构建和Compose尚需在目标运行环境验证。
6. 域名就绪时配置独立Nginx server，使用真实证书和测试者IP访问控制，设置QA_HTTPS=true。必须保留Host；验证`nginx -t`后才允许reload，禁止覆盖旧配置或盲目重启。
7. 先验证9账号权限与付款关闭，再通过安全渠道交付测试网址和密码。账号明文仅在私有0600文件中，不提交PR、不放公开页面。
8. 回滚只停QA容器并切回上一QA镜像，保留QA数据与备份；不执行down -v、不删除现有应用数据、不迁移生产数据库。
