# 部署、迁移与恢复

本轮未连接腾讯云、未修改旧3000/3100/3200服务、未迁移生产数据。先在独立环境验收，禁止把本目录覆盖到旧编辑器。保留旧ZIP与数据卷。

## 开发服务

Node24+，`npm ci && npm run build`。启动时通过进程环境传入初始化管理员与密码；默认loopback。生产目标同域HTTPS反向代理，`/api/v1`与网页同源。`SECURE_COOKIES=true`按请求Host判断Origin，代理须保留公开Host并提供TLS；不信任客户端X-Forwarded-*。Node默认bind loopback，按实际代理网络配置HOST，不直接公网暴露弱认证测试环境。

生产尚缺MFA/找回、防恶意GLB扫描、上传配额/磁盘告警、受限派生模型、错误监控、分布式频控、密钥轮换、真实支付和财务异常处理。不要将验收原型作为正式对外SaaS。

## 备份/恢复

1. 备份目录必须位于数据目录之外。建议先停写，确保数据库、资产、进行中上传在一致运维窗口；脚本使用SQLite在线backup备份数据库，文件复制不是跨存储事务。
2. 执行 `node scripts/backup.mjs /绝对路径/data /不存在的/backup目录`。
3. 执行 `node scripts/verify-backup.mjs /备份目录`，验证文件散列、数据库integrity_check/foreign_key_check、每条已登记资产的文件SHA256。
4. 恢复演练只在新建空目录进行：完整复制已验证备份中的app.sqlite与assets，设置DATA_DIR指向新目录，启动隔离实例；用不同账号检查权限、项目版本、数量与模型散列。不要覆盖运行中的SQLite/WAL。
5. 回滚代码时同时核对PRAGMA user_version；本轮schema版本1，升级未来结构前须编写迁移和回退计划，禁止用旧代码强读新结构。

如果校验失败，备份不能被标记为可恢复。正在上传的tmp分片不进入备份，应由客户端重新续传/重建上传。

## 旧数据盘点

`node scripts/inventory.mjs /旧数据只读目录 > inventory.json`。脚本跳过符号链接，不执行脚本，不修改旧文件。输出含相对路径、字节、SHA256、JSON结构，不输出数据内容。文件散列采用流式读取；16MiB以上JSON只登记散列及大小，完整结构需另做流式审阅。

按真实服务器目录采集后，人工确认owner/workspace、长度单位、模型与商品对应、旧价格可信来源。缺失归属不得导入公共库；不能把旧客户姓名猜为新users。历史报价先作为只读历史记录，不自动生成真实支付/采购订单。本轮只有代码ZIP，无真实项目、模型、数据库，因此未提供会猜测归属的一键导入脚本。

测试部署应设置QA_REVISION为实际发布提交SHA，health返回revision用于区分仓库修复版本和服务器现有版本。通用入口使用APP_REVISION。未设置时显示workspace或unversioned-qa，不能作为发布验收证据。
